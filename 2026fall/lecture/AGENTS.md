# CS182 2026 Fall 课件讲义编写指南

本文件适用于 `E:\CS182\2026fall\lecture\` 及其 `notes/` 子目录。这里的任务是依据**本学期此目录中的官方英文 PDF**，为第一次系统学习机器学习的本科生编写可独立学习的中文讲义。目标是帮助学生理解、推导、手算和应用，不是逐页翻译或压缩 PPT。

## 资料边界与优先级

1. 本目录的官方 PDF 是主要、最权威的课程内容依据。编写或修改某讲义前，实际阅读对应 PDF 的相关页；不要只凭文件名、目录或已有讲义推断内容。
2. `notes/` 中的现有 Markdown 是可修改的教学产物，**不是**高于 PDF 的依据。发现讲义与原课件冲突时核对原页，再解释差异或修正。其他年份的课件、仓库、教材或网页仅在用户另行要求或澄清疑点时使用，不得把它们的安排冒充 2026 Fall 要求。
3. 不修改原 PDF。不根据文件创建日期猜授课顺序、考试范围或当前截止日期；课程通知和新资料可能继续更新。
4. 页码从 PDF 封面算第 1 页。若幻灯片印刷页码不同，明确说明使用哪套编号。关键概念、推导和图旁给可核实的来源，例如“对应课件：`Bayesian_Decision_Theory.pdf`, PDF p.15”。不编造页码、公式、实验结果。
5. 标准教材级的解释、例子和推导可以补充，但与课件内容明确区分，在相应段落或小节标出 **【补充理解】**。若发现课件公式或排版疑似有误，先核对原图、上下文和维度，再给出有理由的勘误；不要默默改写。

## 文件约定与顺序

- 原则上 **一份 PDF 对应 `notes/` 中一份独立 Markdown**；`Course_Overview.pdf` 写成课程地图与学习导航，其余写成真正的教学讲义。长 PDF 也保持一文件，在内部细分章节，不能因为页数多而省略主要知识点。
- 当前对应关系：

- 若出现新 PDF，先扫描新增内容、检查与已有课件的依赖和重叠，确定讲义顺序与下一个编号，再创建对应文件。不要仅按字母顺序或上传时间编号；更新 `00_Course_Overview.md` 的学习地图和需要的跨讲义链接。若只是 PDF 的修订版，先比较内容并更新原对应讲义，避免制造两个互相矛盾的版本。
- 相对链接应从最终的 `notes/` 位置验证：原 PDF 通常写 `../文件名.pdf`，同目录讲义写 `文件名.md`。已有笔记和学生成果不要无故覆盖；修改时保留其有效内容。

## 每个知识点怎样教学

按学生的认知顺序组织，而不是按幻灯片逐句翻译：

1. **问题与动机**：现在到底要预测、估计或优化什么？为什么已有方法不够？
2. **准确的直觉**：优先给一个小而具体的例子。若用重要类比，写明类比中的对象分别对应哪些数学对象，以及类比在哪些地方失效；不要强行打比方。
3. **正式定义**：首次出现的术语用“English term（中文解释）”，有缩写则一并给出。考试是英文，专业词不可只写中文；有助于记忆时解释英文词义。
4. **条件、符号与维度**：说明随机变量还是观测值、标量还是向量/矩阵、样本还是整批数据、参数还是超参数。关键矩阵式标注形状，并检查乘法是否合法。沿用当前 PDF 记号；不同 PDF 记号不同时给出对照，不擅自统一到别的教材。
5. **逐步推导**：先写【推导目标】和【已知条件】，再逐行展示似然/目标构造、代数展开、求导、约束、最优性和结果解释。每个不直观的等号说明所用假设、定理或操作。检查符号、维度、边界情形以及解存在/唯一所需条件；不能用“显然”“取导可得”跳过关键步骤。
6. **数值例子与用途**：重要公式后尽量给真正代入数字、算到结果的例子，并解释它在分类、回归、模型选择等任务中解决什么问题。例子与推导互相核验。
7. **比较与纠错**：明确区分学生易混的概念，尤其 probability/likelihood、PMF/PDF/CDF、prior/posterior、loss/risk、MLE/MAP、PD/PSD 等；给出适用条件与反例，不把直觉或经验趋势说成无条件定理。
8. **理解检查**：以可推理、可手算的问题收尾，通常 5–10 题；答案用 `<details>` 折叠或集中放在末尾，避免一眼看到。学生明确要完整答案时，直接给可核验的完整过程。

可以参考 `notes/` 现有的“问题—前置知识—直觉—定义—推导—数值例子—用途—易错点—English Terminology—知识地图—自测”结构，但按内容调整章节，不机械套模板。每节只推进一个可消化的概念，并指出与前后课件的联系；例如 Probability 的 Bayes' rule → Bayesian Decision Theory 的分类规则 → Parameter Estimation 中先验与类条件密度的估计。

## 数学与图的特别要求

- 概率中分清 \(P(C_i\mid x)\)、\(p(x\mid C_i)\)、\(P(C_i)\)、\(p(x)\)；连续特征的密度值不是单一点概率。likelihood 是固定数据后比较参数的函数，不必对参数归一化。
- 优化中说明目标、约束、乘子符号、强/弱对偶与结论成立条件；梯度、Hessian、特征值、正定性须联系模型训练、曲率或协方差，而不是只列公式。
- 重要图不能忽略。实际查看图，解释横纵轴、曲线/区域含义、老师为什么在这里给图、学生应读出什么；必要时用文字、表格或 Mermaid 重画逻辑。不要根据 PDF 文字提取结果猜图像内容。
- 区分定义、定理、近似、直觉、经验观察和个人推断。遇到课件简写或不严谨处，标清条件与边界，避免让学生形成错误的普遍结论。

## 编写与验收流程

1. 列出本目录所有 PDF，识别新增或修订；针对当前要写的 PDF 读取目录页和全部相关页，必要时渲染图页核对。
2. 先建立覆盖清单：页码范围 → 知识点、关键公式、重要图、与前后讲义的联系。长课件按内部主题分章，但逐项覆盖，不草率批量生成。
3. 一份讲义写完即自查：是否覆盖主要内容，是否真正重新教学，类比是否准确，推导有无跳步，符号维度是否定义，是否有数字例子，英文术语是否保留，来源页码是否可核对，补充内容是否标识。
4. 检查 Markdown 数学定界符和相对链接；抽查数值运算、边界条件、图的解释。发现问题先改完这一份，再继续下一份。
5. 完成后说明新增或修改的文件、检查方式和仍需留意的限制。与用户互动教学时，一次只聚焦一个可消化的点；若基础不明，可用一两个低压力问题确定起点，但不要因此阻碍明确任务。
